# Why aren't we shipping faster now?

Notes on Christian Bird's talk [Why aren't we shipping faster now?](https://cabird.com/talks/shipping-faster/) ([YouTube](https://youtu.be/0wumMeZsNsI)). I recommend watching the video at 1.5x speed.

![Illustration from the talk: five pipes of "new code" pour into a tank of "unshipped" code, which drains through a single "review" filter tended by one person.](blog/shipping-faster/unshipped.png)

Basically the gist is that while coding agents have made code cheaper, all the other parts of releasing are now the significant bottlenecks.

Some interesting takeaways:

- Human reviewers tend to be good at finding maintainability bugs, whereas agents are good at finding severe and reliability bugs. (Reliability bugs here meaning something like "the system performs worse with more load")
- We need to improve the code review process (which Bird says hasn't fundamentally changed since the 70s) to help with the code review bottleneck.
- "Developers lack the time necessary to develop the skills that would save time." The table below gives some of their possible solutions:

![Table 2, Evidence-Based Team Interventions for AI Tool Adoption: clear organizational messaging, AI tool champions, context-specific use cases, knowledge sharing infrastructure, protected learning time, and collaborative sessions.](blog/shipping-faster/interventions.png)

I think the papers referenced in the video have the real meat:

- ["Maybe We Need Some More Examples": Individual and Team Drivers of Developer GenAI Tool Use](https://arxiv.org/abs/2507.21280) (source of the quote and table above)
- [(When) Should a Software Factory Be Lights-Off? Benchmarking Code Review Agents on Bug Detection](https://arxiv.org/abs/2610.13668)
- [Writing Code vs. Shipping Code: Productivity Effects Across Generations of AI Coding Tools](https://www.nber.org/papers/w35275)
- ["To Boldly Go Where No One Has Gone Before": What Has AI Let Developers Unlock?](https://arxiv.org/abs/2610.23708)
- [You Shall Not Pass! Where and Why Developers Draw the Line on AI Autonomy](https://arxiv.org/abs/2607.00533)
